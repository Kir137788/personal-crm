# Круг — личная CRM

Люди, откуда вы знакомы, контакты и заметки после разговоров. Без регистрации, уведомлений и офлайн-режима.

## Запуск

Требуются Node.js 24 LTS, pnpm и запущенный Docker Desktop.

```bash
cd "/Users/kirprovans/Desktop/Курс/module-1/personal-crm"
docker compose up -d --wait
pnpm install
pnpm db:migrate
pnpm db:seed
pnpm build
pnpm start
```

Откройте http://127.0.0.1:3000. Для разработки вместо двух последних команд используйте `pnpm dev`. Приложение работает на Mac, в Docker — только PostgreSQL 18.

Настройки подключения уже находятся в `.env`. Не публикуйте этот файл. На новой машине заполните переменные, перечисленные в `.env.example`: POSTGRES_DB, POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_PORT и DATABASE_URL. Значения в пример не включены. Порт по умолчанию — 5432, адрес базы — 127.0.0.1. DATABASE_URL должен соответствовать остальным параметрам. Пароль не выводится приложением или скриптами.

## Проверка главного сценария

1. Откройте приложение: все контакты доступны в списке по 50 на страницу.
2. Нажмите «Добавить контакт». Имя обязательно; остальные поля необязательны.
3. Закройте карточку и найдите контакт через поле поиска (или ⌘ K).
4. Откройте карточку, допишите заметку, нажмите «Сохранить».
5. Перезагрузите страницу или откройте тот же адрес в другом браузере: контакт и заметка сохранятся.

Поиск не зависит от регистра и работает по всему списку, включая имя, почту, телефон и контекст знакомства. Контакты сортируются по имени. При закрытии карточки с несохранённым текстом приложение просит подтверждение. Если заметка уже изменена в другом окне, приложение не перезаписывает её молча.

## Данные и архитектура

- Next.js App Router, React, TypeScript, Tailwind CSS, локальные компоненты shadcn/ui.
- Браузер обращается только к Next.js API. Доступ к PostgreSQL через Drizzle выполняется на сервере.
- `lib/schema.ts` — схема; `drizzle/` — SQL-миграции и журнал миграций.
- `pnpm db:generate` — создать миграцию после изменения схемы.
- `pnpm db:migrate` — применить миграции.
- `pnpm db:seed` — добавить 1000 вымышленных контактов. Повторный запуск не создаёт дубликаты и не перезаписывает имеющиеся записи.
- Тестовые адреса используют домен example.com; реальные телефонные номера не генерируются.
- После проверки интерфейса дополнительно сохранён один учебный контакт «Вера Тестовая» с заметкой, всего 1001 запись.
- `pnpm typecheck` и `pnpm build` — проверка типов и production-сборки.
- `pnpm-lock.yaml` фиксирует версии зависимостей.

Данные сохраняются в именованном Docker volume `personal-crm_postgres_data`. `docker compose down` останавливает базу с сохранением данных. Не используйте `down -v`, если данные нужно сохранить.

## Работа в Codex

Откройте эту папку как основной локальный проект. `AGENTS.md` подключает инструкции `CLAUDE.md` и запрещает чтение `.env*`. В `.codex/config.toml` задан профиль запрета чтения. Конфигурация загружается в новом сеансе доверенного проекта; управляемые настройки приложения могут иметь приоритет. Скрипты приложения и Compose используют переменные внутри процесса, без вывода секретов.


## Автовыкатка на сервер

Push в `main` запускает `.github/workflows/deploy.yml`: GitHub собирает Docker-образ,
публикует его в GHCR с тегом SHA коммита и вызывает `deploy/ci.sh`.
Сервер скачивает образ, запускает миграции отдельным контейнером из этого же образа,
затем обновляет приложение. Ошибка миграции останавливает выкатку до замены приложения.
Проверки `/health` внутри сервера и через HTTPS должны вернуть 200 и SHA нового коммита.
При ошибке проверки workflow становится красным; автоматического отката нет.

Приложение: https://app.provansov.ru (вход через nginx по логину и паролю).
Проверка доступности: https://app.provansov.ru/health (без авторизации, только статус и версия).
Лендинг https://provansov.ru обслуживается отдельно и не обновляется этим workflow.

### Новая версия

1. Внесите изменения. Если меняется схема базы, создайте и включите SQL-миграцию в коммит.
2. Проверьте `pnpm typecheck` и `pnpm build`.
3. Создайте коммит и отправьте `git push origin main`.
4. Дождитесь зелёного запуска Deploy CRM во вкладке Actions на GitHub.
5. Откройте приложение и проверьте нужный сценарий.

Тестовые данные не добавляются при каждом push. Разовая команда
`ssh crm 'sudo /usr/local/sbin/crm-release seed'` создаёт 1000 вымышленных контактов
и записывает маркер; повторное выполнение ничего не добавляет.

### Устройство сервера

- Docker Compose `-p prod`; настройки: `/opt/personal-crm/compose.yaml`.
- Секреты: `/opt/personal-crm/.env`, владелец root, права 600. Агент файл не читает и не записывает.
- Переменные: `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD`, `DATABASE_URL`.
  База и пользователь — `krug`, внутренний адрес базы — `db:5432`.
- Используется существующий том `krug_postgres_data`. При первом переходе старая пара
  контейнеров останавливается; перед этим создаётся `/opt/personal-crm/before-adoption.dump`.
  Возможен короткий перерыв. Старые контейнеры и исходные настройки сохранены.
- База не публикует порт; приложение слушает только `127.0.0.1:3000`.
- nginx принимает внешний HTTPS. Логи Docker ограничены 3 файлами по 10 МБ на контейнер.
- После успешной выкатки сохраняются текущий и предыдущий SHA-образ этого приложения.
  Старый образ прототипа не удаляется автоматически.
- Ключ CI в GitHub Secrets `DEPLOY_SSH_KEY`; доверенный ключ сервера — `DEPLOY_KNOWN_HOSTS`.
  SSH-ключ CI ограничен forced command: обычный shell, SCP, проброс портов запрещены.
- Сценарии находятся в `deploy/`. Workflow передаёт `remote.sh` серверу;
  сервер принимает только версию, предварительно установленную администратором.
- Root-помощник `/usr/local/sbin/crm-release` принимает только выкатку SHA,
  проверку статуса, разовое заполнение базы и ручной откат. Полного sudo без пароля нет.
- GHCR авторизуется временным токеном запуска Actions; настройки авторизации удаляются после скачивания.

Для первичной установки администратор запускает `sudo bash deploy/install.sh` на сервере,
затем сам подготавливает `.env`. Обновление привилегированного помощника, Compose или
утверждённого `remote.sh` также требует ручной установки через sudo. Обычные изменения
приложения выкатываются автоматически.

### Проверка и ручной откат

```bash
ssh crm 'sudo /usr/local/sbin/crm-release status'
curl --fail https://app.provansov.ru/health
# Только по решению человека; доступен после двух успешных версий:
ssh crm 'sudo /usr/local/sbin/crm-release rollback'
```

Откат переключает образ приложения на предыдущую успешную версию, но не отменяет
миграции базы. Поэтому изменения схемы должны сохранять совместимость с предыдущей
версией приложения. Не применяйте `docker compose down -v`: это удаляет данные.
