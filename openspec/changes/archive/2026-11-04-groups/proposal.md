# Proposal

## Why

По мере роста списка контактов становится трудно быстро выделить людей из нужного круга общения. Пользовательские группы помогут организовать контакты по собственным признакам и находить нужных людей без изменения основного сценария CRM.

## What Changes

- Пользователь сможет создавать группы с произвольными названиями, а также переименовывать и удалять их.
- Один контакт можно будет включить в любое количество групп при создании и позже в карточке контакта.
- Группы будут показаны метками в списке и карточке контакта.
- Список контактов можно будет отфильтровать по одной группе либо показать контакты без групп; текстовый поиск продолжит работать внутри выбранного фильтра.
- Названия групп будут обязательными и уникальными без учёта регистра и пробелов по краям.
- Удаление группы удалит только связи с контактами; сами контакты и их данные сохранятся.
- Существующие контакты после миграции останутся без групп.
- Для новой логики появятся unit-тесты на Vitest, написанные по TDD. Настройка e2e и CI в это изменение не входит.

## Capabilities

### New Capabilities

- `contact-groups`: создание и управление группами, включение контактов в несколько групп, отображение групп и фильтрация списка.

### Modified Capabilities

Нет.

## Impact

- Схема PostgreSQL и миграция: таблица групп и таблица связей контактов с группами.
- Серверные запросы, типы и API контактов; отдельные операции управления группами и составом групп.
- Форма создания, карточка и общий список контактов в существующем тёплом адаптивном интерфейсе.
- Проектная настройка Vitest, тестовая команда и unit-тесты новой логики.
- Новая библиотека времени выполнения не требуется; Vitest добавляется только как инструмент разработки.
