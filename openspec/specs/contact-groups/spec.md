# contact-groups Specification

## Purpose

Пользовательские группы помогают организовать личные контакты по нескольким кругам общения и быстро находить нужных людей в общем списке CRM.

## Requirements

### Requirement: Создание группы
Система SHALL позволять пользователю создавать группу с непустым произвольным названием. Пробелы по краям удаляются, а сохранённая группа сразу становится доступна для назначения контактам и фильтрации.

#### Scenario: Группа создана
- **WHEN** пользователь вводит название «Теннис» и сохраняет группу
- **THEN** группа «Теннис» появляется в списке групп и доступна для назначения без перезагрузки страницы

#### Scenario: Пустое название
- **WHEN** пользователь пытается сохранить название, состоящее только из пробелов
- **THEN** группа не создаётся, пользователь видит понятную ошибку и может исправить название

#### Scenario: Повторяющееся название
- **WHEN** группа «Друзья» уже существует и пользователь пытается создать « друзья » или «ДРУЗЬЯ»
- **THEN** новая группа не создаётся, существующая группа не меняется и пользователь видит ошибку о повторе

### Requirement: Переименование группы
Система SHALL позволять переименовать существующую группу по тем же правилам названия. Новое название применяется ко всем меткам и фильтрам, не меняя состав группы.

#### Scenario: Успешное переименование
- **WHEN** пользователь переименовывает группу «Теннис» в «Большой теннис»
- **THEN** новое название видно у всех ранее включённых контактов, а состав группы сохраняется

#### Scenario: Конфликт при переименовании
- **WHEN** пользователь переименовывает группу в название, уже занятое другой группой без учёта регистра и пробелов по краям
- **THEN** название не меняется, состав обеих групп сохраняется и пользователь видит ошибку

### Requirement: Удаление группы без удаления контактов
Система SHALL запрашивать подтверждение перед удалением группы. Подтверждённое удаление удаляет группу и все её связи с контактами, но сохраняет сами контакты, их заметки и настройки напоминаний.

#### Scenario: Удаление подтверждено
- **WHEN** пользователь подтверждает удаление группы, в которой есть контакты
- **THEN** группа и её метки исчезают, а все входившие в неё контакты остаются доступны со своими данными

#### Scenario: Удаление отменено
- **WHEN** пользователь отменяет подтверждение удаления группы
- **THEN** группа, её название и состав остаются без изменений

### Requirement: Несколько групп у контакта
Система SHALL позволять назначить контакту любое количество разных существующих групп при создании контакта и позже в его карточке. Повтор одной группы не создаёт дубликат связи.

#### Scenario: Новый контакт в нескольких группах
- **WHEN** пользователь создаёт контакт и выбирает группы «Друзья» и «Теннис»
- **THEN** контакт сохраняется один раз и после создания состоит в обеих группах

#### Scenario: Изменение групп существующего контакта
- **WHEN** пользователь в карточке добавляет одну группу, убирает другую и сохраняет
- **THEN** новый состав групп сохраняется между сеансами, а остальные данные контакта не меняются

#### Scenario: Неизвестная группа
- **WHEN** при сохранении передан идентификатор несуществующей группы
- **THEN** состав групп контакта не меняется частично, пользователь получает ошибку и может повторить сохранение

### Requirement: Отображение групп
Система SHALL показывать группы контакта метками в общем списке и в карточке контакта. Контакты без групп остаются видимыми и доступными для назначения.

#### Scenario: Контакт с группами
- **WHEN** контакт входит в несколько групп
- **THEN** список и карточка показывают каждую назначенную группу без дубликатов

#### Scenario: Существующий контакт после миграции
- **WHEN** пользователь открывает контакт, существовавший до появления групп и ещё не распределённый по ним
- **THEN** контакт отображается без групп, его прежние данные сохраняются и ему можно назначить группы

### Requirement: Фильтрация списка
Система SHALL предлагать фильтры «Все», каждая существующая группа и «Без группы». Одновременно выбирается один фильтр, а текстовый поиск применяется внутри его результата.

#### Scenario: Фильтр конкретной группы
- **WHEN** пользователь выбирает группу «Аналитики»
- **THEN** в общем списке остаются только контакты этой группы, включая контакты, которые одновременно состоят в других группах

#### Scenario: Фильтр без группы
- **WHEN** пользователь выбирает «Без группы»
- **THEN** в списке остаются только контакты, которым не назначена ни одна группа

#### Scenario: Поиск внутри группы
- **WHEN** выбран фильтр группы и пользователь вводит текст в поиск
- **THEN** показываются только контакты, которые одновременно входят в группу и соответствуют поиску

#### Scenario: Возврат ко всем контактам
- **WHEN** пользователь выбирает «Все»
- **THEN** групповой фильтр снимается, а список снова охватывает все контакты с учётом текущего текста поиска

### Requirement: Ошибки не создают ложного состояния
Система SHALL сохранять последнее подтверждённое состояние групп при сетевой ошибке или недоступности базы и показывать понятную ошибку с возможностью повторить действие.

#### Scenario: Ошибка сохранения
- **WHEN** создание, переименование, удаление или изменение состава групп не завершилось на сервере
- **THEN** интерфейс не сообщает об успехе, не показывает неподтверждённые изменения как сохранённые и позволяет повторить действие
